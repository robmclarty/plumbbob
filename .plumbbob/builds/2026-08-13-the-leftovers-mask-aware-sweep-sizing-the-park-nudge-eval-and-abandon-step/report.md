# Report — the leftovers: mask-aware sweep sizing, the park-nudge eval, and abandon-step

Three recorded deferrals, each with its own paper trail, batched into one build
because none blocked another (D1 (one-build-batch)): the em-dash sweep's
"size the next sweep honestly" tangent, the eval tier's missing c5 baseline arm,
and the paragraph in the `recover` commit that scoped abandon out by name.
All three are closed.

## What shipped

**An honest sizing instrument.** The em-dash sweep's queues had lied in both
directions: vale collapses multi-line paragraphs when positioning findings, so
`docs/decisions.md` listed 85 where the file really held nearly 200, while raw
grep over-counts by including the code spans the rule correctly ignores. The fix
is one shared masking module, `scripts/prose-mask.ts`, covering fenced blocks,
inline spans, and indented blocks, now feeding both the citation scanner and a
new `scripts/count-prose.ts` (wired as `pnpm size:prose`). The mask's contract is
CommonMark, which is vale's own scope, rather than guessed intent
(D14 (commonmark-parity)): a four-plus-space run masks only where an indented
block can legally start, so this repo's bullet-heavy two-space house style counts
as the prose it is. `--show-masked` prints every masked indented span, so the one
remaining approximation (deep list context) is auditable instead of trusted.

**Two blind spots found by using it.** Running the counter against its own
surfaces turned up a mask that stopped at the line end, so an inline code span
wrapping a line break read as prose and over-counted exactly what vale ignores
(D15 (wrapped-code-spans), live in `skills/verify/SKILL.md`). It also turned up
that `scripts/**/*.ts` sat outside the citation scanner's surface entirely, which
had been hiding twelve real violations in the three files this build had just
touched (D16 (scripts-in-refs-scan)). Ten of those were build-local `D#` tags
colliding with the global key, which is now a stated rule rather than a habit:
shipped code under `src/` or `scripts/` cites `docs/decisions.md` and nothing
else, and a build-local decision is named in words until a step promotes it
(D17 (global-tags-only-in-code)).

**The park nudge's missing control arm.** The nudge had been measured once, at
0.9.0, but never against a baseline, so nothing isolated its effect. Both arms
ran at 0.10.0 at n=5 (D10 (both-arms)), generated by the driver's `--report`
rather than hand-authored (D4 (derived-receipt)), and landed as
`docs/evals/2026-08-14.md`: **c5 baseline 3/5 versus latched 5/5**. The nudge is
worth two runs in five, measured rather than assumed. Because the latched arm
read a clean 5/5, well above the 3/5-or-worse trigger, the conditional reword in
step 6 was struck unbuilt and the nudge stays as written
(D13 (nudge-stays)).

**A third exit from an in-flight step.** Until now a step in flight had two
exits, and both took the work with them: `checkpoint` lands it, `revert` destroys
it. `plumbbob abandon` drops the attempt and keeps the working-tree diff exactly
where it is. It ships as its own verb rather than a `recover` repair or a
`revert` flag (D5 (abandon-verb)), because this is a loop transition rather than
a repair of inconsistent state, which is the reasoning the scoping-out commit
gave for deferring it in the first place. Its whole contract is what it refuses
to touch (D6 (tree-untouched)): it clears the in-flight markers, appends a
build-log line (D8 (abandon-log-line)), and writes nothing else. The step keeps
its `[ ]` and stays re-buildable, because abandon drops the attempt rather than
the intention (D7 (stays-planned)). It honors the same approval latch as
checkpoint (D9 (abandon-latched)), which is load-bearing rather than decorative:
abandon clears the entry stamp the latch reads, so an unlatched abandon followed
by a same-turn checkpoint would have reopened the side door D67
(auto-not-a-grant) closed. That composed case is pinned by test.

**The surface that teaches it.** A shipped third exit under guidance that still
taught two would make the most-read prose lie, so every site that enumerates the
exits was found by grep rather than memory (D11 (third-exit-teaching)): the new
`skills/abandon/SKILL.md` driver, the revert and recover skills, the skills, CLI,
state-and-git, and troubleshooting docs, and the `recover` and `spike` refusal
strings in `src/`. `docs/decisions.md` gained **D79 (abandon-keeps-work)**,
promoting the scoping-out rationale from a commit body into the key.

## Parked and harvested

Three items parked, all three called **blocker** by Rob, no tangents and no pivot
signals. That ratio is itself unusual and worth naming: each one was a fault in
an instrument this build was in the middle of building, found by pointing the
instrument at itself.

- **The wrapped code span** (harvested after step 2) became
  D15 (wrapped-code-spans) and landed as a new step 3.
- **The unscanned `scripts/` surface** (harvested after step 2) became
  D16 (scripts-in-refs-scan) and D17 (global-tags-only-in-code) and landed as a
  new step 4. What made it a blocker rather than a tangent was an ordering
  hazard: step 7 writes `src/verbs/abandon.ts`, `src/` is scanned, and its
  done-when cited build-local tags that step 8 would not promote until later.
  Both fixes were sequenced ahead of the abandon work so the scanner was honest
  before that code was written.
- **Two stray `D15` cites left by step 3's own fix** (harvested after step 3)
  needed no new decision; it rode under the standing
  D17 (global-tags-only-in-code) and corrected step 4's done-when tally from
  eight tags to ten.
